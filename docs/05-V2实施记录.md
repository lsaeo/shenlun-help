## 四、实施中解决的坑

1. **httpx 无 apparent_encoding**（那是 requests 属性）→ 改用 charset_encoding。
2. **gov.cn 列表页 JS 渲染抓不到** → 改为抓 gov.cn 首页全链接 + URL 日期提取（`/202608/content_`），并只保留含日期且在 14 天窗口内的条目。
3. **config 合并逻辑不覆盖旧值** → 用户已有 config.json 的 sources 仍是旧 RSS 源，需显式迁移脚本升级（保留 api_key）。
4. **前端 setTimeout 全局变量跨 runJavaScript 不可靠** → 测试改为"switchTab 后固定等待 + 直接读 DOM"，应用本身无 bug。
5. **FakeLLM 缺新方法** → test_dedup 补 pick_hotspots 等。
6. **AI 挑选失败降级**：无 key/超时时按最新日期取前 N 条，保证流水线不中断。

## 五、与方案的偏差

1. **news.cn 域名**：方案写"新华网时政"用 `http://www.news.cn/politics/`，实测 http 重定向到 https，直接用 https。
2. **gov.cn 日期精度**：gov.cn URL 只有年月（`/202608/content_`），日期取当月 1 号；因其内容几乎都是近 1-2 天发布的要闻，14 天窗口判断不受影响。
3. **话题卡去重**：沿用 V1 的"当天主题去重"（次日重新生成），未改成按"14 天"——保持每日新鲜。
4. 其余无功能性偏差。

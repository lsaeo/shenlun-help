## 三、实施中解决的坑

1. **FastAPI 路由冲突复发**：`/api/expressions/locate` 被 `/api/expressions/{item_id}` 吞掉（与 phrases/filter 同款问题）。修复：locate 移到 CRUD 注册之前。**教训：凡有静态路径 + 动态路径的集合，静态路径必须先注册。**
2. **范文自动抓取可行性**：必应搜索可用（百度反爬），但公开可抓的完整范文页稀缺（知乎/头条反爬、多数站点为索引页）。方案按"抓几篇算几篇 + 手动粘贴兜底"落地，实测抓到 3 篇候选（含搜狐素材文）。
3. **范文正文导航噪声**：`fetch_article_text` 逐行过滤导航/广告词（首页/登录/注册/课程等），正文质量提升。
4. **测试网络超时**：`/api/fanwen/fetch` 是同步网络抓取，测试需长超时（90s），失败可接受。
5. **数据迁移**：真实 data/ 初始化 cases 种子 8 个；config 合并自动补新字段。

## 四、与方案的偏差

1. 范文"3 选 1"：实测公开可抓范文稀缺，`fetch_fanwen_candidates` 不硬性要求 3 篇（抓到几篇算几篇），并保留手动粘贴路径。
2. 拆解树维度详情用 `<details>` 原生折叠实现（方案要求"点击展开"，等价）。
3. 其余无功能性偏差。

## 三、实施中解决的坑

1. **~$ 临时文件**：Word 打开时生成 `~$xxx.docx` 锁文件，python-docx 打不开会抛错 → scan_sucai 跳过 `~$` 前缀。
2. **docx 内多篇拆分**：实测标记为「范文一话题：XXX」（无空格），正则 `^范文([一二三四五六七八九十百\d]+)话题[:：]` 精确匹配。
3. **测试文本长度**：300 字阈值对单元测试文本太长，改用 30 字局部阈值验证拆分逻辑 + 单独断言 MIN_FANWEN_LEN==300。
4. **FakeLLM 缺新方法**：test_dedup 补 `parse_fanwen_template`。
5. **在线抓取清理**：server.py 3 个 API + fetchers.py 全套代码删除，polish 测试同步适配。

## 四、与方案的偏差

1. **系统文件对话框（QFileDialog）未实现**：QWebEngineView 内嵌浏览器无法直接弹 Qt 对话框（需 JS 桥）。改为**前端列出 sucai/ 文件 + 点击解析**（`/api/fanwen/list-files`），功能等价、实现更简单。若用户确需任意位置选文件，后续加 QWebChannel 桥接。
2. `from-fanwen` 保留为手动粘贴入口（原"候选确认"逻辑随在线抓取移除）。
3. 其余无功能性偏差。

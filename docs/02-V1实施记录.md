## 三、实施中解决的坑（记录备查）

1. **pip 安装卡死**：官方 PyPI 下载 PySide6 极慢（10 分钟无输出）。改用清华镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple` 秒装。**教训：本机后续装包一律用镜像。**
2. **FastAPI 路由冲突**：`/api/phrases/filter` 被先注册的 `/api/phrases/{item_id}` 动态路由吞掉。修复：filter 路由必须先于动态路由注册。
3. **前端渲染测试假阴性**：QWebEngineView 冷启动慢，3 秒时 app.js 未执行完；且跨 `runJavaScript` 的 setTimeout 全局变量不可靠。修复：轮询等待 JS 就绪 + 直接读 DOM。**应用本身无 bug。**
4. **流水线日期推进 bug**：完全失败时仍推进 `last_update_date`，会掩盖"漏更"。修复：只有生成了内容才推进日期。
5. **set_config 无法置空**：`v is not None` 过滤导致 `last_update_date` 无法重置。修复：允许显式 None（前端总是传完整字段，无副作用）。

## 四、与方案的偏差

1. **新闻源选择**：方案九说"新闻源从新华网 RSS + 中国政府网开始"。实施时默认源为**人民网时政 RSS + 新华网时政 RSS**（两者均实测抓取成功），中国政府网的 HTML 列表抓取代码（`fetchers.py` 的 `fetch_html_list`）已实现但未放入默认源——HTML 列表页选择器最脆弱、维护成本最高，留作备用源可在设置中添加。
2. **热点字段**：hotspots 的"考点分析"（意义/角度/对策/金句）按方案扁平化为顶层字段，未嵌套。

其余无功能性偏差。

# 语段库每日搜集与 AI 改稿机制（V1 补充方案）

- 状态：**已确认**
- 日期：2026-08-26
- 依赖：[01-V1方案说明](01-V1方案说明.md)、[02-V1实施记录](02-V1实施记录.md)

## 一、背景与目标

V1 原方案中语段库为纯人工积累（种子 56 条 + 手动录入），不参与每日流水线。用户明确新需求：

> **网络搜集和 AI 改稿并行**：从网上搜集可用语段；若搜集到的语段缺填空框架（template）和改写例句（examples），由 AI 改写成与种子一致的格式（text + template + examples + 三维标签 + usage）。

## 二、机制设计

### 2.1 每日流水线新增"语段搜集"步骤

每日流水线（与热点、话题卡同一次触发）追加：

1. **抓取素材页**：从配置的 `phrase_sources`（语段素材源 URL 列表，默认收录中公/华图等公开素材页）抓取正文文本。
2. **切分候选语段**：按段落/标点切分正文，过滤过短/过长的噪声行，产出候选列表。
3. **去重**：与 `phrases.json` 现有语段比较（标题/正文相似度），跳过已收录内容，避免每天重复入库。
4. **AI 改稿**：对每个新候选调用 LLM，输出与种子一致的标准结构：
   ```json
   {"text": "语段原文", "template": "填空框架(____占位)", "examples": ["改写例句1", "改写例句2"],
    "position": ["开头|结尾|过渡|论证"], "theme": ["民生|生态|..."], "technique": ["排比|对仗|引用|比喻|设问|递进"], "usage": "适用场景"}
   ```
5. **入库为草稿**：status=草稿，等待人工审核；审核通过才进入正式语段库。

### 2.2 配置项

`config.json` 新增：

| 键 | 默认值 | 说明 |
|---|---|---|
| `daily_phrases` | 3 | 每日最多新增语段条数（草稿） |
| `phrase_sources` | 2 个默认素材页 | 语段素材源 URL 列表，可在设置中维护 |

### 2.3 审核流

与热点/话题卡完全一致：AI 产物一律 `status=草稿`，应用内逐条"入库/编辑/删除"。用户可在设置页将 `daily_phrases` 设为 0 关闭此功能。

## 三、与既有功能的关系

- 语段库仍以**人工积累为主体**（种子 56 条 + 手动录入），每日搜集是"增量补充"，不是替代。
- 去重保证：每天抓同一素材页不会产生重复草稿。
- 手动录入弹窗已支持 template/examples 字段，格式与 AI 产物一致。

## 四、边界（不做）

- 不做自动审核入库（AI 内容永不直接进库）。
- 不维护素材页结构变化（页面改版导致抓取失败 → 当日跳过语段搜集，不影响热点/话题卡）。
- 不自动扩充主题词表（新语段 theme 只能落在现有 8 个主题内，由 LLM 归类）。

## 二、用户决策汇总（拷问结论）

| 决策点 | 结论 |
|---|---|
| 轮转粒度 | **按单篇范文轮转**（拆分 .docx 内"范文N"为独立篇） |
| 轮转完了 | **解析完停止 + 检测到 sucai 新增文件自动恢复** |

| 短篇处理 | **自动跳过 <300 字**的篇，不再轮 |

## 三、设计

### 3.1 范文索引（新增 `data/fanwen_index.json`）

扫描 sucai/ 下的 .docx/.txt/.xml，按"范文N/话题："标记拆分出单篇：

```json
{
  "files": [
    {
      "path": "sucai/第一篇 社会治理类.docx",
      "mtime": "2026-08-27T10:00:00",
      "articles": [
        {"id": "f1", "title": "范文一话题：城市治理数字化", "content": "全文…", "status": "已解析"},
        {"id": "f2", "title": "范文二话题：…", "content": "全文…", "status": "待解析"}
      ]
    }
  ]
}
```

- `status`: 待解析 | 已解析 | 已跳过（<300 字自动跳过）
- 新文件（mtime 变化或新路径）→ 自动加入队列，status=待解析
- 已解析/已跳过的篇不再轮转；**新增文件自动恢复轮转**

### 3.2 每日轮转（并入流水线）

每日流水线新增步骤（与热点/话题卡同次触发）：
1. 扫描 sucai/ 重建索引（检测新增文件）
2. 取第一个 `status=待解析` 的篇（按文件顺序 → 篇内顺序，均衡轮转）
3. 调 LLM `parse_fanwen_template` 解析成模板 → 存 templates.json
4. 该篇 status 标记"已解析"
5. 所有篇已解析/已跳过 → 本轮结束，等待新文件

### 3.3 手动解析（系统对话框）

- 框架栏"范文模板"区新增按钮"**解析本地文件**"
- QFileDialog 选 .docx/.txt/.xml（可多选）→ 解析 → 存 templates.json
- 与每日轮转独立，不占用轮转状态（手动选的文件不标"已解析"，可重复解析）

### 3.4 移除在线抓取

- `fetchers.fetch_fanwen_candidates` / `search_bing` / `fetch_article_text` 相关代码移除
- 前端"抓取范文候选"按钮移除，替换为"解析本地文件"
- `_SEARCH_QUERIES`、`_is_index_page` 保留为遗留工具或清理（实施时定）

### 3.5 AI 提供商预留

- config.json 新增 `ai_provider: "deepseek"`（当前仅一项）
- 设置页加"AI 提供商"下拉（现仅"DeepSeek API"），灰显说明"更多提供商（免费本地/通义等）开发中"
- 后端 LLM 客户端保持可插拔：`DeepSeekClient` 抽象为按 provider 选择，本次仅注册 deepseek

### 3.6 依赖

- 新增 `python-docx`（已可用，写入 requirements.txt）
- .txt 直接读；.xml 解析为纯文本后读

## 五、边界（不做）

- 不做免费 AI 接入（本轮仅预留切换位）
- 不做 .doc/.wps 旧格式（需另装转换组件；如用户有需求再说）
- 不做范文正文深度清洗（保留原文段落）

## 六、验收标准

1. 扫描 sucai/ 13 个文件拆分为 N 篇范文，索引正确
2. 每日流水线自动解析一篇待解析范文 → 存模板库 → 标记已解析
3. 全部解析完 → 停止；新增 .docx 到 sucai/ → 自动恢复轮转
4. 手动选文件（系统对话框）可解析任意 .docx/.txt/.xml
5. <300 字短篇自动跳过
6. 设置页显示 AI 提供商下拉（仅 DeepSeek，预留位可见）
7. 在线抓取代码移除，全量回归通过
